# Plan 08.1-01 — Auth refresh hardening

## Defect

On cold extension activation when the stored access token is past its `expires_at`, the side panel renders:

> Failed: The access token has expired.

…instead of either (a) silently refreshing via `refresh_token`, or (b) resetting to the sign-in welcome view when refresh is impossible.

## Root cause (3 layers)

1. **Scope omission** — `package.json` `altium365.scopes` default + all 3 env-specific overrides (Dev/Uat/Prod, lines 200/237/246/255) lack `offline_access`. Auth0 / IdentityServer (Altium's IdP) only issue `refresh_token` when `offline_access` is requested. Result: `TokenSet.refresh_token` is always `undefined` after sign-in.
2. **`src/auth.ts:554-570 getBaseAccessToken`** — guards refresh on `base.refresh_token` (always undefined per #1) and returns the stale expired token on the `else` branch, which then 401s. Even when refresh exists but throws, the `catch {}` swallows the error and again returns the stale token.
3. **`src/auth.ts:395 exchangeWorkspaceToken`** — reads `getStoredTokens` directly; no expiry/refresh awareness. Once #1+#2 are fixed, this is still a latent failure for the workspace-scoped token-exchange path.

## Tasks (atomic commits)

1. **package.json scopes** — prepend `offline_access` to `altium365.scopes` default and all 3 environment defaults. **Commit:** `fix(08.1-01): request offline_access scope so IdP issues refresh_tokens`
2. **`getBaseAccessToken` recovery** — when `isExpired(base)` and either `!base.refresh_token` OR `refreshTokens` throws, call `clearAllTokens(context)` and return `undefined`. The existing `onAuthStateChanged` wiring (`extension.ts:155-158`) then updates `altium365.signedIn=false` and refreshes the tree → welcome view renders. **Commit:** `fix(08.1-01): reset to welcome view when base token expires and refresh is impossible`
3. **`exchangeWorkspaceToken` guard** — route the base-token read through `getBaseAccessToken(context, cfg)` (instead of `getStoredTokens`) so an expired base triggers refresh before the token-exchange GraphQL call. Re-fetch the full `TokenSet` via `getStoredTokens` after the refresh side-effect to get the fresh `subject_token`. **Commit:** `fix(08.1-01): refresh base token before workspace token exchange`
4. **`refreshTokens` revocation handling** — on `postForm` throw (4xx from IdP = revoked/invalid refresh_token), clear all tokens before re-throwing so caller's `catch` resets the welcome view. **Commit:** `fix(08.1-01): clear tokens on refresh_token revocation to bump to welcome view`

## UAT (deferred — user-driven post-rebuild)

1. **Happy path refresh** — fresh sign-in → confirm stored token has `refresh_token` field (peek via Developer: Inspect Context Keys or a throwaway debug command) → manually edit `expires_at` to past, OR wait for natural expiry → reload window → tree should silently populate without error.
2. **Refresh-token revoked** — sign in → revoke session server-side (or hand-edit `refresh_token` to garbage) → reload → expect welcome view ("You are not signed in to Altium 365" with Sign In button), **not** an error row.
3. **No regression** — sign-in, workspace selection, list scripts/projects, run a script — all still work.

## Out of scope

- Proactive background refresh before expiry (current model is reactive on next request — acceptable)
- Multi-account / account-switch UX
- Persisting `last_refresh_at` for telemetry
