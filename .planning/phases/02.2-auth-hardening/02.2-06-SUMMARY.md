# Phase 02.2 Plan 06: Call-Site Migration to Refresh-Aware Base Token Summary

Swapped the two base-scope GraphQL call sites (`sidePanel.loadWorkspaces`, `workspace.pickAndExchangeWorkspace`) from raw `getStoredTokens(...).access_token` to the refresh-aware `getBaseAccessToken(ctx, cfg)` accessor introduced in plan 02.2-02; in the second call site additionally swapped the workspace-scope exchange from `exchangeWorkspaceToken` to the mutex-guarded, cached `ensureWorkspaceToken` per locked D-10.

## What changed

### `src/sidePanel.ts` (commit `33da9c2`)

- Import: removed `getStoredTokens`, added `getBaseAccessToken`.
- `loadWorkspaces`: replaced the `getStoredTokens` + `access_token` access pattern with a single `getBaseAccessToken(this.ctx, cfg)` call; removed the now-defunct `void cfg;` placeholder (cfg is now consumed).
- All downstream behaviour (empty-list info node, workspaceUrl derivation, node mapping, cache assignment) preserved verbatim.

### `src/workspace.ts` (commit `70ac7fb`)

- Imports: removed `getStoredTokens`, `exchangeWorkspaceToken`, `TokenSet`; added `getBaseAccessToken`, `ensureWorkspaceToken`.
- `pickAndExchangeWorkspace` list step: `getStoredTokens(context)` + `base.access_token` → `getBaseAccessToken(context, cfg)`. Error message preserved: `"Sign in first (Altium 365: Sign In)."`.
- `pickAndExchangeWorkspace` exchange step: `exchangeWorkspaceToken(context, cfg, pick.ws.authId)` → `ensureWorkspaceToken(context, cfg, { workspaceId: pick.ws.workspaceId, authId: pick.ws.authId })`. This routes through the per-workspaceId mutex (dedup of concurrent exchanges) and the cache-hit fast path from plans 02.2-04 / D-07 / D-08.
- Return type narrowed `Promise<TokenSet | undefined>` → `Promise<string | undefined>` (ensureWorkspaceToken returns the access_token string).
- `globalState.update('altium365.selectedWorkspace', pick.ws)` persistence preserved.

### Caller (`src/extension.ts:160` — read only)

Verified `doSelectWorkspace` only performs `if (tok)` truthiness — no member access on `tok`. The narrowed return type compiles unchanged. `extension.ts` was not modified (listed in `<files_modified>` only to authorize re-reading; no edit needed).
