<objective>
Eliminate the cross-workspace token-confusion bug (CR-01) and the WR-05 carry-forward (workspace token leaking to base-scope GraphQL calls) by replacing the `SECRET_WORKSPACE_TOKENS` singleton with a routing model that consults the user's explicit workspace selection.

Purpose: per D-02 the "active" workspace is the user's explicit selection — never the most-recently-exchanged. Per D-03 a sibling `getBaseAccessToken` exists so base-scope callers (`listWorkspaces`) never accidentally receive a workspace-scoped token.
Output: refactored `src/auth.ts` with the singleton gone, two clearly-named token accessors (`getBaseAccessToken`, `getActiveAccessToken`), and the `getStoredWorkspaceTokens` export removed.
</objective>
