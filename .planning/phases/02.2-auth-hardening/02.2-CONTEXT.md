<decisions>
## Implementation Decisions

### Token Routing (CR-01)
- **D-01:** Drop the `SECRET_WORKSPACE_TOKENS` singleton entirely. It was the source of the cross-workspace token-confusion bug. All workspace-scoped storage lives under `SECRET_WS_TOKEN_PREFIX + workspaceId`.
- **D-02:** `getActiveAccessToken(context, cfg)` resolves to `ensureWorkspaceToken(context, cfg, selectedWorkspace)` when a workspace is selected (via `getSelectedWorkspace`), falling back to the refresh-aware base token when no workspace is selected. The "active" workspace is the user's *explicit selection*, never the most-recently-exchanged.
- **D-03:** Introduce a sibling helper `getBaseAccessToken(context, cfg)` that returns only the base token, applying refresh-on-expiry. `loadWorkspaces` and any future base-scope GraphQL call uses this — not `getActiveAccessToken`. This closes the 02.1 WR-05 concern (preventing workspace-scoped tokens from being handed to `listWorkspaces`).
- **D-04:** Remove `getStoredWorkspaceTokens` from the public surface — no callers should reach into the (now-removed) singleton. Keep `getStoredTokens` (base) public; it's still needed for id_token claims.

### Sign-In Drain (CR-02)
- **D-05:** Call `clearAllTokens(context)` at the top of `signIn`, BEFORE the OAuth dance. Defensive: any prior identity's per-workspace cache must not survive a new sign-in, even when the user skipped explicit sign-out.
- **D-06:** Suppress the transient `signedIn: false` event that `clearAllTokens` fires during the sign-in flow. Either pass a `{ silent: true }` flag into `clearAllTokens`, or refactor the emitter fire out of `clearAllTokens` and into the two call sites that actually mean "user is now signed out" (the explicit sign-out command + the sign-in failure cleanup). Planner picks the smaller refactor.

### Race Fix (02-REVIEW WR-05)
- **D-07:** Introduce a tiny in-process `AsyncMutex` helper (no deps, ~20 LOC). Use it to serialize read-modify-write of `GLOBAL_WS_TOKEN_INDEX_KEY` in `ensureWorkspaceToken`. The same Mutex (keyed by `workspaceId`) ALSO deduplicates concurrent `exchangeWorkspaceToken` calls for the same workspace, so a cold-start tree expansion across N workspaces does N exchanges, not N×concurrent-callers exchanges.
- **D-08:** Mutex helper lives in a new file `src/asyncMutex.ts` (single-purpose, testable in isolation when test infra arrives later). Not exported from any barrel — auth.ts imports it directly.

### Refresh-Aware Token Reads (WR-02 + 02.1 WR-05)
- **D-09:** `loadWorkspaces` in `src/sidePanel.ts` calls `getBaseAccessToken(this.ctx, readOAuthConfig())` instead of `getStoredTokens(...).access_token`. Same change applies to `pickAndExchangeWorkspace` for its `listWorkspaces` call.
- **D-10:** `pickAndExchangeWorkspace` itself uses `getBaseAccessToken` to fetch the list, then `ensureWorkspaceToken` to acquire/refresh the workspace-scoped token. Two-step is intentional and explicit.

### XSS + Error-Body Hygiene (WR-01 + WR-04)
- **D-11:** Add a small local `escapeHtml` helper inside `src/auth.ts` (not exported — only one site uses it). Use it on the OAuth `error` query param before interpolating into the loopback error page.
- **D-12:** Apply `.slice(0, 500)` to the token-endpoint error body in `postForm` (line 99). Matches the existing truncation in the non-JSON-body branch on line 104.

### Telemetry / Logging
- **D-13:** No new logging or telemetry in this phase. The OutputChannel suggestion from IN-06 (log `clearAllTokens` partial failures) is deferred — IN-* items are out of scope.

### Claude's Discretion
- Exact shape of `AsyncMutex` API (`acquire()/release()` vs `runExclusive(fn)`) — planner picks the simpler one.
- Whether D-06's silent flag is a parameter on `clearAllTokens` or a refactor moving the fire to call sites — planner picks the smaller diff.
- Whether `getBaseAccessToken` lives alongside `getActiveAccessToken` in `auth.ts` or in a new module — keep in `auth.ts` unless it would push the file past ~500 lines.

### Verification (Manual UAT — D-14)
The planner produces a UAT script covering:
1. **Account switch without explicit sign-out** — sign in as A, expand a workspace (caches token), sign in as B without signing out → confirm A's per-workspace cache is gone (inspect via Developer Tools or by triggering a workspace expand that would 401 on A's token).
2. **Parallel workspace expansion** — collapse all, refresh tree, immediately expand 3+ workspaces. Confirm exactly N token exchanges occur (one per workspace), no duplicates in the OutputChannel or network log.
3. **Expired base token** — manually expire the base token (set `expires_at` to past via Developer Tools, or wait), then trigger a tree refresh → confirm refresh-token flow runs and tree loads, no 401.
4. **listWorkspaces with workspace selected** — select a workspace, then refresh tree → confirm `listWorkspaces` was called with the BASE token (not the workspace-scoped one), via network log.
5. **OAuth error XSS** — manually craft a callback URL with `?error=<img src=x onerror=alert(1)>` and confirm the loopback page renders the escaped text, no script execution.

<code_context>
## Existing Code Insights

### Reusable Assets
- `withExpiry()` + `isExpired()` helpers already exist in `auth.ts` — reuse for any new code paths
- `refreshTokens()` already implements the refresh_token grant against `SECRET_TOKENS` — `getBaseAccessToken` wraps it
- `GLOBAL_WS_TOKEN_INDEX_KEY` index pattern is established and `clearAllTokens` already drains via it — Mutex slots in around this existing logic

### Established Patterns
- All token storage via `context.secrets.{get,store,delete}` — no plaintext, no globalState for token material (globalState only holds the index of which workspaceIds have a cached token)
- Errors surface at command boundary via `vscode.window.showErrorMessage` — auth functions throw, command handlers in `extension.ts` catch
- `authStateEmitter` is the singular auth-state broadcast channel (CONVENTIONS.md exception) — fired from `signIn` (true) and `clearAllTokens` (false). D-06 will need care here.

### Integration Points
- `extension.ts` `pickAndExchangeWorkspace` — calls both `getBaseAccessToken` (new) for `listWorkspaces` AND `ensureWorkspaceToken` for the exchange
- `sidePanel.ts` `loadWorkspaces` — single-line swap from `getStoredTokens(...).access_token` to `getBaseAccessToken(this.ctx, readOAuthConfig())`
- `treeCommands.ts` — no change (Open in Browser doesn't touch tokens beyond what's in the node payload)

### Anti-patterns to avoid
- Don't reintroduce a singleton "active workspace token" — that was the source of CR-01
- Don't `fire({ signedIn: false })` from `signIn`'s pre-drain (handled by D-06)
- Don't add a global lock — Mutex must be keyed (per workspaceId for exchange dedup, single key for the index update)

</code_context>

<specifics>
## Specific Ideas

The 02.1 fix-skip note (`02.1-REVIEW-FIX.md` WR-05 row) is the key constraint: the naive `getActiveAccessToken → ensureWorkspaceToken` swap leaks a workspace-scoped token to `listWorkspaces`. D-03 (`getBaseAccessToken`) is the surgical fix for that constraint — keep it explicit at every call site.
</specifics>

## Deferred Ideas

- **Auth integration tests** — meaningful tests for the race fix and token-routing model need vscode-test + mocha infrastructure. Belongs in its own phase (proposed Phase 4-pre or after the milestone closes).

- **Multi-account UX** (Sign in as different user without sign-out) — D-05 makes this safe at the token layer, but the UX (account picker in status bar, multiple identities at once) is a future feature, not a hardening pass.
