      - `class AsyncMutex` with one public method:
        - `runExclusive<T>(key: string, fn: () => Promise<T>): Promise<T>`

    Semantics:
      - Calls with the SAME key are serialized in FIFO order — the second call's `fn` starts only after the first call's returned promise settles (resolve OR reject).
      - Calls with DIFFERENT keys run independently in parallel.
      - If `fn` throws (sync) or rejects (async), the lock for that key MUST be released before the rejection propagates so the next waiter proceeds.
      - The lock entry for a key may be left in the map after the queue drains; do not over-engineer cleanup. Workspace count is bounded.

    Implementation shape (directive — do not inline code in PLAN.md per planner rules; executor writes the source):
      - Private `private locks = new Map<string, Promise<unknown>>()`
      - `runExclusive` reads the current tail promise for the key (or `Promise.resolve()` if absent), chains its `fn` onto it via `.then(fn, fn)` or an explicit `try/finally` wrapper that ensures the chain continues even on rejection, then writes the resulting promise back as the new tail.
      - The returned promise to the caller must reflect `fn`'s outcome (resolve with fn's value, reject with fn's error), NOT the tail-chain promise (which must be swallowed of errors to keep the chain unbroken — wrap in a `.catch(() => {})` for the tail-write only).

    File header: short JSDoc explaining purpose (per-key async serialization), the D-07/D-08 reference, and the CONVENTIONS exception note (single-purpose helper module; the internal `locks` Map is intentional module-local state).
