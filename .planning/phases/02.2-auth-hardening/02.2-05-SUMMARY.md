# Phase 02.2 Plan 05: Auth Hygiene (XSS escape + error-body truncation) Summary

Two independent defensive hardening fixes in `src/auth.ts`: HTML-escape the OAuth `error` query param before interpolating it into the loopback response page (D-11 / WR-01), and apply `.slice(0, 500)` to the token-endpoint HTTP-error body in `postForm`'s `!res.ok` branch (D-12 / WR-04).

## What Changed

1. **D-11 (WR-01)** — Added non-exported `escapeHtml(s: string): string` helper directly below `pkcePair` (src/auth.ts:87-104). Single-pass regex `/[&<>"']/g` with a replacement table covering the five HTML-sensitive characters (`&` first via table semantics — regex match order is irrelevant when replacement is table-driven). Used in the `awaitCallback` `if (error)` branch (line 151): `${error}` → `${escapeHtml(error)}` in the response HTML body. A callback URL with `?error=<img src=x onerror=alert(1)>` now renders escaped literal text — no script execution.

2. **D-12 (WR-04)** — `postForm` line 115: `${text}` → `${text.slice(0, 500)}` in the `!res.ok` throw, matching the existing truncation in the non-JSON-body branch (line 120). A chatty maintenance-page error body can no longer flood the OutputChannel / error toast.

Both edits land in regions untouched by plan 02.2-02 (commit `1cc8424`, which modified token-routing functions further down the file).
