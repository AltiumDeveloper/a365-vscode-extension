# Phase 02.2 Plan 03: signIn Pre-Drain + Silent Emitter (D-05, D-06) Summary

One-liner: `signIn` now drains any prior identity's base + per-workspace token cache before the OAuth dance via a silent `clearAllTokens` variant, closing CR-02 without producing a transient `signedIn:false` UI flicker.

## What Changed

**`src/auth.ts` (+16 / −5):**

1. `clearAllTokens` signature widened from `(context)` to `(context, options?: { silent?: boolean })`. The drain body (delete `SECRET_TOKENS`, enumerate `GLOBAL_WS_TOKEN_INDEX_KEY`, delete each `SECRET_WS_TOKEN_PREFIX+id`, clear the index) is unchanged. The `authStateEmitter.fire({ signedIn: false })` is now wrapped in `if (!options?.silent)`. Existing try/catch around the fire preserved.
2. `signIn` gained `await clearAllTokens(context, { silent: true })` as the first executable statement (with an explanatory D-05/D-06 comment), before `pkcePair()`, redirect setup, and `awaitCallback`.

## Implementation Shape

Shape A from the plan's `<interfaces>` note. TypeScript compiled cleanly on first attempt — no need to pivot to Shape B (which would have split the change across `auth.ts` + `extension.ts`). Both existing non-signIn callers in `extension.ts` (line 144 `doSignOut`, line 259 environment-switch sign-out) remain zero-arg and therefore still fire `signedIn:false` loudly to subscribers (status bar, side panel).
