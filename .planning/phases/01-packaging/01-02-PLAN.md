    1. Download the latest `.vsix` from the [GitHub Releases](https://github.com/altium/a365-vscode-extension/releases) page (or from the CI artifacts).

    3. Reload VS Code when prompted.

    **## Getting Started** section — three numbered steps:
    1. **Sign in** — Run **Altium 365: Sign In** from the Command Palette. Your browser opens and completes the OAuth2 login. Tokens are stored in VS Code's secure secret storage.
    2. **Select a workspace** — Run **Altium 365: Select Workspace**. Pick a workspace from the list. A workspace-scoped token is obtained and stored automatically.
    3. **Run a script** — Open any `.py` file that defines `onExecute(context, input_parameters)`. Click the run button (▷) in the editor title bar or right-click the file in the Explorer and choose **Altium 365: Run Python Script**.

    **## Running and Debugging Scripts** section:
    - Describe the script contract: the extension calls `onExecute(context, input_parameters)` where `context.auth_token` is the current A365 access token, `context.graphql_url` is the GraphQL endpoint, and `input_parameters` is a dict loaded from `<script>.params.json` (next to the script) or from the `altium365.inputParametersPath` setting.
    - Mention the bundled `a365` helper: `import a365` is available; `a365.query("query { __typename }")` calls the A365 GraphQL API using the active token.
    - For debugging: run **Altium 365: Debug Python Script** from the Command Palette or editor title bar. This launches the script under the VS Code debugger (breakpoints supported).

    **## Switching Environments** section:
    - Run **Altium 365: Select Environment (Dev / Uat / Prod)** from the Command Palette.
    - Three environments are pre-configured: Dev (`usw2.dev-365.altium.com`), Uat (`eur.uat-365.altium.com`), Prod (`eur.365.altium.com`).
    - Switching environments clears the active workspace and workspace token — sign in again with **Altium 365: Select Workspace** after switching.
    - Custom environments can be defined under `altium365.environments` in VS Code settings.

    **## Commands Reference** section — a markdown table with columns "Command" and "Description":
    | Command | Description |
    | --- | --- |
    | Altium 365: Sign In | Opens browser for OAuth2 login and stores tokens |
    | Altium 365: Sign Out | Clears all stored tokens |
    | Altium 365: Select Workspace | Lists accessible workspaces and stores a workspace-scoped token |
    | Altium 365: Select Environment (Dev / Uat / Prod) | Switches the active A365 environment |
    | Altium 365: Run Python Script | Runs the active `.py` file against the A365 API |
    | Altium 365: Debug Python Script | Runs the active `.py` file under the VS Code debugger |

    **## Configuration** section — mention key settings:
    - `altium365.pythonPath` — path to Python interpreter (default: auto-detect)
    - `altium365.inputParametersPath` — path to a JSON file passed as `input_parameters` (default: looks for `<script>.params.json`)
    - `altium365.promptForProjectId` — whether to prompt for a projectId if no params file is found (default: true)
    - `altium365.environments` — object of named environments; each can override graphqlEndpoint, authEndpoint, tokenEndpoint, scopes
