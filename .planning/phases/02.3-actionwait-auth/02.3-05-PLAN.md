<objective>
Make sign-in cancellable from the VS Code UI and present the distinct, D-12-mandated error messages to the user. After plan 04, `signIn` accepts an optional `AbortSignal` and throws errors with specific message prefixes that this plan pattern-matches at the call site.

Purpose: D-09 requires a cancellable progress notification wired through an AbortController. Without this plan, the user sees the generic "Sign-in failed: <raw error>" toast — which leaks internal error wording and doesn't match the D-12 contract.

Output: a rewritten `doSignIn` function in `src/extension.ts` with a cancellable progress wrap, AbortController plumbing, env-config pre-flight check, and a switch-style error mapper. No other function in `src/extension.ts` is touched.

    2. **Wrap signIn in a cancellable progress notification** per D-09. Replace the existing `vscode.window.withProgress` block with:
       ```
       const controller = new AbortController();
       try {
           await vscode.window.withProgress(
               {
                   location: vscode.ProgressLocation.Notification,
                   cancellable: true,
                   title: 'Altium 365: waiting for sign-in...',
               },
               async (_progress, token) => {
                   const cancelSubscription = token.onCancellationRequested(() => controller.abort());
                   try {
                       await signIn(context, cfg, 180_000, controller.signal);
                   } finally {
                       cancelSubscription.dispose();
                   }
               }
           );
           vscode.window.showInformationMessage('Altium 365: signed in.');
           await updateSignedInContext(context);
           const choice = await vscode.window.showInformationMessage('Pick a workspace now?', 'Select workspace');
           if (choice === 'Select workspace') {
               await doSelectWorkspace(context);
           }
       } catch (e) {
           // see step 3
       }
       ```
       Key points:
       - `cancellable: true` is what surfaces the Cancel button on the notification.
       - The `_progress` parameter is unused — prefix with underscore to satisfy any `noUnusedParameters` tsconfig flag (check `tsconfig.json`; if not set, the underscore is still a project convention courtesy).
       - The `cancelSubscription.dispose()` in the inner finally prevents the event listener from leaking if signIn completes (success or failure) without cancellation firing — `vscode.Disposable` returned from `onCancellationRequested` must be disposed.
       - The 180_000 timeout is passed explicitly to make the contract visible at the call site; relying on signIn's default would work but obscures the D-09 wall-clock cap.

    3. **Implement the D-12 error mapper** in the `catch (e)` block. Use a helper closure to keep the function readable:
       ```
       const msg = (e as Error).message ?? String(e);

       // Silent cancellation per D-12 — the closing progress notification IS the feedback.
       if (msg === 'Sign-in cancelled.') {
           return;
       }

       // CSRF guard (exact match per D-07/D-12)
       if (msg === 'State mismatch (possible CSRF).') {
           vscode.window.showErrorMessage('Altium 365 sign-in failed: state mismatch (possible CSRF).');
           return;
       }

       // Wall-clock timeout
       if (msg.includes('wall-clock timeout')) {
           vscode.window.showErrorMessage('Altium 365 sign-in timed out after 3 minutes. Please try again.');
           return;
       }

       // Network error during poll — message format from plan 04: 'ActionWait network error: <err> (<host>)'
       if (msg.startsWith('ActionWait network error')) {
           // Extract the host from the trailing parenthesised group; fall back to the actionWaitEndpoint host.
           const hostMatch = msg.match(/\\(([^)]+)\\)\\s*$/);
           let host = hostMatch ? hostMatch[1] : '';
           if (!host) {
               try { host = new URL(cfg.actionWaitEndpoint).host; } catch { host = cfg.actionWaitEndpoint; }
           }
           vscode.window.showErrorMessage(
               `Altium 365 sign-in failed: cannot reach ActionWait service (${host}). Check network connectivity.`
           );
           return;
       }

       // ActionWait non-2xx HTTP status — message format from plan 04: 'ActionWait returned <status>: <body>'
       if (msg.startsWith('ActionWait returned')) {
           const statusMatch = msg.match(/^ActionWait returned (\\d+)/);
           const status = statusMatch ? statusMatch[1] : '?';
           vscode.window.showErrorMessage(`Altium 365 sign-in failed: ActionWait returned ${status}.`);
           return;
       }

       // Token endpoint failure or anything else — existing pass-through preserved (D-12 final bullet)
       vscode.window.showErrorMessage(`Sign-in failed: ${msg}`);
       ```

Network and HTTP-status checks come before the catch-all (their messages share the "ActionWait" prefix — anchoring on `startsWith` keeps them disjoint). The catch-all at the end preserves the existing "Sign-in failed: <message>" behaviour for token-endpoint failures and any unanticipated error.
