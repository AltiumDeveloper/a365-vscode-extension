## Decisions & rationale (per `<output>` requirements)

### (a) `pollActionWait` 200-body field names

**Pinned to working assumption: `{ code: string, state: string }`** (CONTEXT.md D-05).

Parser at the top of the 200 branch:
```ts
const code = parsed?.code;
const state = parsed?.state;
if (typeof code !== 'string' || code.length === 0 ||
    typeof state !== 'string' || state.length === 0) {
    throw new Error(`ActionWait returned 200 but response body is missing code or state: ${text.slice(0, 500)}`);
}
return { code, state };
```

**Confidence:** No corroborating evidence for or against alternative field names was discovered during this plan's execution — this plan was a pure src/auth.ts rewrite with no network calls or ActionWait documentation to consult. The parser is **isolated**: only the property accesses on lines reading `parsed?.code` / `parsed?.state` need to change if the actual shape differs. The rest of the flow (state-equality CSRF check in `signIn`, token exchange) is field-name-agnostic — it consumes the `{code, state}` shape returned by `pollActionWait`.

**Recommended UAT action for plan 02.3-05 / dev1 sign-in:** Capture the literal 200 response body (e.g. via `console.log(text)` between `await res.text()` and `JSON.parse(text)`) on first successful authorization to confirm/reject the field-name assumption. If different, update both the parser and the error message string `'... missing code or state: ...'`.

### (b) AbortSignal aggregation: manual wiring (NOT `AbortSignal.any`)

`AbortSignal.any([userSignal, timeoutSignal])` is the spec-clean composition but only available on **Node 20+**. AGENTS.md declares the project baseline as **Node ≥18**. Manual wiring is portable across the supported range:

```ts
const internalController = new AbortController();
if (signal.aborted) {
    internalController.abort();
} else {
    signal.addEventListener('abort', () => internalController.abort(), { once: true });
}
const timeoutHandle = setTimeout(() => internalController.abort(), timeoutMs);
try {
    /* poll loop — passes internalController.signal to fetch */
} finally {
    clearTimeout(timeoutHandle);  // guarantee timer cleanup on every exit path
}
```

The `{ once: true }` listener option prevents leaking a permanent listener if `pollActionWait` exits before the caller cancels. The `finally` block clears the setTimeout on **every** exit path (success / cancellation / network error / status branches), eliminating handle leaks.

## Error message strings thrown by new code

The strings below are the EXACT text thrown by the rewritten `src/auth.ts` — these are the contract plan 02.3-05 must pattern-match for D-12 user-facing toast mapping. Listed in expected encounter frequency / mapping-significance order:

| String | Thrown by | Maps to D-12 user message |
|---|---|---|
| `Sign-in cancelled.` | `pollActionWait` on 410, on caller-signal abort, on AbortError with `signal.aborted==true` | Silent (suppressed per D-12) |
| `State mismatch (possible CSRF).` | `signIn` after CSRF check | "Sign-in failed (security check)" |
| `ActionWait poll exceeded <N>ms wall-clock timeout.` (N = `timeoutMs`, default 180000) | `pollActionWait` deadline branch + AbortError with `signal.aborted==false` | "Sign-in timed out after 3 minutes" |
| `ActionWait returned <status>: <body-truncated-to-500>` | `pollActionWait` on any status ≠ 200/408/410 | "ActionWait returned <status>" |
| `ActionWait returned 200 but body is not JSON: <body-truncated-to-500>` | `pollActionWait` 200 branch, JSON.parse failure | Falls through to generic "Sign-in failed" toast |
| `ActionWait returned 200 but response body is missing code or state: <body-truncated-to-500>` | `pollActionWait` 200 branch, missing/empty `code` or `state` field | Falls through to generic "Sign-in failed" toast (and is the canary for the D-05 field-name assumption — if it fires reliably during UAT, the assumption is wrong) |
| `ActionWait network error: <e.message> (<host>)` | `pollActionWait` on non-AbortError fetch rejection (DNS / TCP refused / TLS / etc.) | "Network error reaching <host>" |

Plan 02.3-05 substring matchers to use (suggested):
- `wall-clock timeout` → timeout branch
- `Sign-in cancelled.` → cancellation branch (suppress)
- `State mismatch` → CSRF branch
- `ActionWait network error` → network branch
- `ActionWait returned ` → fatal-status branch (catches both "ActionWait returned 4xx/5xx" and the two "ActionWait returned 200 but ..." variants)
