<objective>
Replace the loopback HTTP-server OAuth callback with Altium's ActionWait long-poll service in `src/auth.ts`. This is the core of Phase 02.3 — a single coherent rewrite of the OAuth flow's callback mechanism contained in one file per project convention (CONTEXT.md line 33: "sole owner of OAuth flow; surface change is in this file").

Purpose: D-10 mandates the loopback code is gone outright (no fallback, no opt-in). D-11 mandates the new poll function lives in the same file as a private helper. D-13 mandates the Phase 02.2 auth surface (`clearAllTokens` pre-drain, `getBaseAccessToken` / `getActiveAccessToken` / `ensureWorkspaceToken` / `workspaceTokenMutex` / `getStoredTokens` / per-workspace index / auth state emitter) is bit-for-bit invariant — this plan must NOT touch any of those exports' bodies.

Why one plan, not three: the type change to `OAuthConfig` makes the current `signIn` body fail to compile (it reads `cfg.redirectPort` and `cfg.redirectPath`). The only way to land the type change without a temporary tsc break is to rewrite `signIn` in the same diff. Removing `awaitCallback` and `escapeHtml` while `signIn` still references the former is also a tsc break. So OAuthConfig + readOAuthConfig + dead-code removal + pollActionWait + signIn rewrite form a single atomic change to one file. Coarse granularity per project config makes this the right shape.

Output: a fully rewritten `src/auth.ts` that compiles, preserves every Phase 02.2 export's behaviour, removes the loopback dance, and introduces the ActionWait poll + new signIn body.

    1. **Add the `pollActionWait` private helper** near the top of the file, after `postForm` (around the current line ~131) and before `withExpiry`. Exact signature per D-11:
       ```
       async function pollActionWait(
           endpoint: string,
           connectionToken: string,
           signal: AbortSignal,
           timeoutMs: number
       ): Promise<{ code: string; state: string }>
       ```

       Implementation directive (prose):

       - Compute the wall-clock deadline once: `const deadline = Date.now() + timeoutMs;`.
       - Construct an internal `AbortController` whose `.signal` is what gets passed to each `fetch` call. Wire two abort sources to it:
         - Caller signal: if `signal.aborted` already, abort internal immediately. Otherwise add a one-shot listener `signal.addEventListener('abort', () => internalController.abort(), { once: true });`.
         - Timeout: `const timeoutHandle = setTimeout(() => internalController.abort(), timeoutMs);` — but compute remaining time per iteration too (see below) and reset the handle accordingly. Simpler implementation: ONE setTimeout for the full `timeoutMs` since the deadline is absolute. Clear it in a `finally` block to avoid leaking handles.
       - Enter a loop. On each iteration:
         - Compute `remaining = deadline - Date.now()`. If `<= 0`, throw `Error('ActionWait poll exceeded ' + timeoutMs + 'ms wall-clock timeout.')` — plan 05's error-mapper will translate this to the D-12 "timed out after 3 minutes" message by matching on substring "wall-clock timeout".
         - If `signal.aborted` (caller signal — checked before the fetch to avoid an extra network round-trip on already-cancelled flow), throw `Error('Sign-in cancelled.')`.
         - Issue the fetch:
           ```
           const res = await fetch(endpoint, {
               method: 'POST',
               headers: { 'Content-Type': 'application/json' },
               body: JSON.stringify({ token: connectionToken }),
               signal: internalController.signal,
           });
           ```
           Wrap in try/catch. On catch:
             - If the error's `name === 'AbortError'` OR `signal.aborted` is now true: caller cancelled → throw `Error('Sign-in cancelled.')`.
             - If the error's `name === 'AbortError'` AND `signal.aborted` is false (only the internal timeout fired): throw `Error('ActionWait poll exceeded ' + timeoutMs + 'ms wall-clock timeout.')`.
             - Otherwise it's a network-layer error (DNS, refused connection, TLS, etc.): re-throw with a wrapped message that includes the endpoint host so plan 05 can format the D-12 network message. Shape: `throw new Error('ActionWait network error: ' + (err as Error).message + ' (' + new URL(endpoint).host + ')');` — note: `URL` from 'url' import must be available; if Task 1 removed the named `URL` import, re-add it (`import { URL, URLSearchParams } from 'url';`).
         - Branch on `res.status`:
           - `200`: read body via `await res.text()`, parse as JSON. Default field names are `code` and `state` (working assumption per D-05; if empirical UAT reveals different names, adjust the parser HERE and document in SUMMARY — the rest of the flow is field-name-agnostic). Validate both fields are non-empty strings; if either is missing, throw `Error('ActionWait returned 200 but response body is missing code or state: ' + text.slice(0, 500));`. Return `{ code, state }`.
           - `408`: continue the loop (server-side per-request timeout per D-05 — reconnect with the same connection_token).
