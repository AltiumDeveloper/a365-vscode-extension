# Phase 02.3 Plan 05: Cancellable Sign-In + D-12 Error Mapping Summary

**One-liner:** Rewrote `doSignIn` in `src/extension.ts` to wrap `signIn` in a cancellable progress notification, thread an AbortController into plan-04's optional signal parameter, pre-flight the new env-config fields, and map the seven distinct error strings thrown by `pollActionWait`/`signIn` to the six D-12 user-facing toasts (including the silent-cancel branch).

## What changed in `src/extension.ts`

**doSignIn (lines 111–141 → 111–204):**

1. **Added pre-flight check** for `cfg.actionWaitEndpoint` and `cfg.redirectUri` — both populated by `doSelectEnvironment` (plan 02). Empty either ⇒ user gets a clear remediation toast pointing at the env-switch command.
2. **Replaced progress wrap** with `cancellable: true`, title `'Altium 365: waiting for sign-in...'`, and a `(_progress, token)` callback that wires `token.onCancellationRequested(() => controller.abort())`. The subscription is disposed in an inner `finally` to prevent listener leaks on normal completion.
3. **Passed `controller.signal`** as the 4th argument to `signIn(context, cfg, 180_000, controller.signal)` — exercising the optional parameter that plan 04 added.
4. **Replaced the catch-all toast** with a 6-branch error mapper, ordered for disjointness:
   - `msg === 'Sign-in cancelled.'` → silent return (the closing progress notification IS the feedback)
   - `msg === 'State mismatch (possible CSRF).'` → "Altium 365 sign-in failed: state mismatch (possible CSRF)."
   - `msg.includes('wall-clock timeout')` → "Altium 365 sign-in timed out after 3 minutes. Please try again."
   - `msg.startsWith('ActionWait network error')` → extracts trailing `(host)` (or falls back to `new URL(cfg.actionWaitEndpoint).host`) → "...cannot reach ActionWait service (\<host\>)..."
   - `msg.startsWith('ActionWait returned')` → extracts numeric status (covers `4xx/5xx` AND both `200 but ...` malformed-body variants — status will be `200` for those, which is informative) → "...ActionWait returned \<status\>."
   - Catch-all → "Sign-in failed: \<message\>" (existing token-endpoint pass-through preserved per D-12 final bullet)

**Everything else in `src/extension.ts`:** untouched. The three call sites of `doSignIn` (line 52 command registration, line 338 post-env-switch, line 502 401-retry) continue to invoke with a single argument — the signature is unchanged.

## Error-mapping table (vs. plan 04's thrown strings)

| Thrown by auth.ts (plan 04) | Branch in doSignIn | User-facing toast |
|---|---|---|
| `Sign-in cancelled.` | equality | (silent) |
| `State mismatch (possible CSRF).` | equality | `Altium 365 sign-in failed: state mismatch (possible CSRF).` |
| `ActionWait poll exceeded 180000ms wall-clock timeout.` | `includes('wall-clock timeout')` | `Altium 365 sign-in timed out after 3 minutes. Please try again.` |
| `ActionWait network error: <e> (<host>)` | `startsWith('ActionWait network error')` | `Altium 365 sign-in failed: cannot reach ActionWait service (<host>). Check network connectivity.` |
| `ActionWait returned <4xx/5xx>: <body>` | `startsWith('ActionWait returned')` | `Altium 365 sign-in failed: ActionWait returned <status>.` |
| `ActionWait returned 200 but body is not JSON: <body>` | `startsWith('ActionWait returned')` | `Altium 365 sign-in failed: ActionWait returned 200.` |
| `ActionWait returned 200 but response body is missing code or state: <body>` | `startsWith('ActionWait returned')` | `Altium 365 sign-in failed: ActionWait returned 200.` (D-05 canary) |
| Any postForm token-endpoint error | catch-all | `Sign-in failed: <message>` |

Branch ordering guarantees disjointness: the silent-cancel and CSRF equality checks fire before any substring/prefix match could capture them.
