## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| status-bar click → QuickPick → command id | user-driven; delegates only to whitelisted existing command ids |
| id_token claims (user label) | display-only, derived in Plan 02 with try/catch fallback |
| `altium365.activeEnvironment` setting | user-controlled string; rendered as plain text in status bar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-01 | Spoofing (display label phishing) | user label in status bar | accept | Inherits Plan 02 T-02-02-05 disposition; label source is IdP-issued id_token. |
| T-02-05-02 | Tampering (status-bar QuickPick injects arbitrary command) | onStatusBarClick delegation | mitigate | Whitelisted three command ids hard-coded into the items array; `pick.command` typed as `string` but only ever one of the three literals. No user input parsed into a command id. |
| T-02-05-03 | Information Disclosure | label leakage in screenshots/recordings | accept | User explicitly opts into showing identity in status bar by signing in. Standard VS Code UX (Git, GitHub extensions do the same). |
| T-02-05-04 | DoS (render spam) | onAuthStateChanged subscription | mitigate | render() is debounced naturally — only fires on auth-state events (few per session); render does an awaitable getStoredTokens call; concurrent renders are tolerated because StatusBarItem.text/show/hide are idempotent setters. |
| T-02-05-05 | Stale label after env switch | env name in label | mitigate | Plan 04 Task 2 step 6 adds `fireAuthStateChanged({ environment: pick.name })` after env update; Plan 05 Task 2 step 5 verifies the call is present (defensive duplicate if missing). |
| T-02-05-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages added in this plan. |
</threat_model>
