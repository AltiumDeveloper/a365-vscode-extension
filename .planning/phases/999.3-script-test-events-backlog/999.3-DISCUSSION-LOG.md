## Storage scope

| Option | Description | Selected |
|--------|-------------|----------|
| globalState | Events follow the user across all VS Code windows. Mental model matches the existing lastProjectId cache (already on globalState per extension.ts:831). | ✓ |
| workspaceState | Per VS Code window. Matches Phase 3 D-05 original reservation. Trade-off: opening from a different workspace folder = no events. | |
| globalState with per-workspace override | Hybrid: global default, per-workspace overrides win when present. Added complexity for an edge case. | |

**User's choice:** globalState (Recommended)
**Notes:** Aligns with the existing lastProjectId pattern. The original Phase 3 D-05 reservation mentioned workspaceState but is superseded.

## Sibling .params.json interop

| Option | Description | Selected |
|--------|-------------|----------|
| One-time import prompt, then state wins | Prompt to import on first run when sibling exists and no state entry exists. After import, state wins; file is left in place but marker set. | ✓ |
| Coexistence — file overrides state | File always wins when present. Two sources of truth, divergence inevitable. | |
| Hard deprecation — warn and ignore | Show deprecation warning, ignore file. Simplest but punitive. | |
| Promote sibling to first-class "file-backed" event | Sibling appears in picker as a pseudo-event read from disk each invocation. Best UX but more resolver code. | |

**User's choice:** One-time import prompt, then state wins (Recommended)
**Notes:** Marker key prevents re-prompt. File is NOT deleted (deleting user files = hard no per CONTEXT D-08).

## Standalone .py support

| Option | Description | Selected |
|--------|-------------|----------|
| v1: registered scripts only | Test events only work for scripts with a remote identity. Standalone files keep existing sibling + projectId-prompt fallback. | |
| Standalone supported — key by fsPath | Simple but breaks when file moves; orphans in globalState. | |
| Standalone supported — key by content hash | Survives renames but breaks on every save (new hash = new identity). | |
| Standalone supported — key by workspace-relative path | Survives workspace moves; breaks for files outside any workspaceFolder. | |
| (User clarification) Global pool of events for local files | Single shared pool; user picks at run-time; last-pick remembered by fsPath. | |
| (After re-discussion) Per-script storage uniformly; fsPath identity for standalone | Same UX for remote and local; identity = scriptId for remote, fsPath for standalone. | ✓ |

**User's choice:** Per-script storage uniformly; fsPath as identity for standalone local .py.
**Notes:** User initially suggested a global shared pool, then reverted to per-script after re-discussion. Quote: "Let's return to the original idea - we keep events per each script individually, for both remote and local ones. Local scripts are keyed by fsPath, as suggested earlier. Similar experience, regardless of local/remote distinction." fsPath fragility (move = orphan) explicitly accepted.

## Default-event invocation semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Silent default everywhere; prompt only on first run | Submenu + palette use default silently. First run prompts to create or pick default. | ✓ |
| Always silent default (explicit picker is only switch path) | Default always wins. To switch, user must open picker UI explicitly. | |
| Palette prompts, submenu silent | Mixed model. Palette = interactive context. Submenu = button-press. | |
| Always prompt | Every invocation prompts. Predictable but high friction. | |

**User's choice:** Silent default everywhere; prompt only on first run (Recommended)
**Notes:** Matches AWS Toolkit Lambda behavior — default event runs unattended; explicit picker is one extra click via the test-events sub-menu/dropdown.

## UI placement of the events picker

| Option | Description | Selected |
|--------|-------------|----------|
| Sub-row inside the existing Altium 365 submenu | A fifth row "Test events ▸" appended to the Phase 6 branded submenu. | ✓ (both shipped) |

**User's choice:** Ship both #1 and #2 for visual A/B trial. Quote: "Let's add both #1 and #2 - I need to see them both to decide which one to keep. Design accordingly - assume that there will be only one place at the end."
**Notes:** Shared command handlers (`altium365.testEvents.*`); only `package.json` `contributes.menus` differs between the two placements. Post-UAT cleanup is a single `package.json` edit (remove one menu group).

## Edit UI

| Option | Description | Selected |
|--------|-------------|----------|
| JSON virtual document with JSONSchema | Open as JSON in a regular tab via virtual scheme. Save-bridge commits to globalState. Reuses VS Code's JSON editor. | ✓ |
| JSON temp file (mirrors Phase 6 tmp-script layout) | Same as #1 but file on disk. More disk activity but matches Phase 6 D-09..D-12 exactly. | |
| Structured form WebView | Custom WebView with form inputs. Better UX, much more code. | |
| QuickPick-only — no JSON editor in v1 | Events created via repeated QuickPick prompts. Edit = delete + recreate. | |

**User's choice:** JSON virtual document with JSONSchema (Recommended)
**Notes:** Virtual scheme keeps the OS tmpdir clean and avoids file-management bookkeeping. Save-bridge pattern from Phase 6 is the model.
