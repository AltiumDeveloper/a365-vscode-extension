## Decisions Made
- **Delete-default policy** — `deleteEvent` (store.ts:59) clears `defaultEventName` to empty string when the deleted event was the default; picker omits the default-header row when defaultName doesn't resolve to an existing event; next resolver-path run enters the 4b branch and dispatches `setDefault`. Passive-clear chosen over auto-promote because explicit re-selection is safer when multiple events remain (e.g., a user deleting `production-default` shouldn't silently promote `experimental-fixture` to default).
- **Project-related preset auth orchestration** — wrapped `pickProjectId` in `pickProjectIdSafe` with three tiers: (1) active workspace + minted token → full picker with project list; (2) no workspace OR no endpoint → `showInputBox` for manual GUID; (3) token mint failure → `showInputBox` with reason logged to outputChannel. UAT confirmed both no-workspace manual path and live workspace project-list path work correctly.
- **Picker module is pure UX** — no globalState writes, no command dispatch; the discriminated-union return shape (`{kind:'event'} | {kind:'create'} | {kind:'edit-default'} | {kind:'empty'}`) keeps the caller in commands.ts responsible for side effects. This allows the same picker to be reused with `eventsOnly:true` from edit/delete/setDefault without modification.
- **Identity argument shape from resolver** — resolver dispatches command with the full `ScriptIdentity` object (not just the string identity); `resolveIdentityOrWarn` accepts either an explicit identity object (resolver path) or falls back to `resolveScriptIdentity(activeEditor.uri)` (palette path). Single command surface, two invocation contexts.
