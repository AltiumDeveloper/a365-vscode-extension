# Phase 999.3 — Script Test Events Phase Summary

**AWS-Lambda-style named test events for script parameters — multiple named templates per script, shared across local run / debug / remote execute, edited as JSON with schema validation, surfaced via picker + status bar + editor-title submenu.**

## Outcome

Replaces the legacy single-value `altium365.inputParametersPath` setting (removed end-to-end in Plan 06) with a per-script multi-event model. A developer can now:

1. Open any script (local `.py` or `altium365://` remote).
2. See the test-event indicator in the status bar (count + default name).
3. Click → Create / Edit / Delete / pick default via one unified Quick Pick.
4. Run locally or execute remotely — both paths resolve parameters via the same `resolveScriptParameters(scriptIdentity)` helper.

Events persist in `globalState` (per-user, cross-workspace) keyed by `altium365.scriptParams.<identity>`. Identity is the remote `scriptId` UUID for tracked scripts, or a normalized fsPath for standalone local scripts.

## Key Architectural Decisions (chronological)

- **D-04..D-06 (Plan 01):** `ScriptIdentity` discriminated union (`remote`/`local`) with identity = scriptId UUID OR normalized fsPath. Pure module, no FSP machinery pulled in.
- **D-15..D-18 (Plan 03):** Custom `FileSystemProvider` on scheme `altium365-event:` (NOT `registerTextDocumentContentProvider` which is read-only). Dual-layer JSONSchema: declarative `contributes.jsonValidation` + runtime `$schema` injection on read.
- **D-20..D-22 (Plan 02):** Unified `resolveScriptParameters(identity)` helper consumed by both `prepareRun` (local) and `executeRemoteScript` Block B (remote). Removes the divergence Phase 6 D-05 only patched at the surface. `altium365.promptForProjectId` becomes a no-op (later removed in Plan 06).
- **D-21 (Plan 06):** Bloat warning at >25 events per identity, fires from `.create` only (not edit/setDefault), one-time per identity via `altium365.scriptParams.bloatWarned.<identity>` flag.
- **D-12 (Plan 05→06):** A/B trial of submenu (Placement A) + title-bar button (Placement B). **Outcome:** Placement B removed in UAT iter 5; status bar indicator + Placement A submenu is the final placement.
