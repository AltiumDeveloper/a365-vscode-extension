## Pattern Assignments

### `src/testEvents/eventFs.ts` (FileSystemProvider)

**Analog:** `src/remoteScriptFs.ts:143` `AltiumRemoteScriptFs`

**Class skeleton — copy verbatim** (`remoteScriptFs.ts:143-188`):
```typescript
export class AltiumRemoteScriptFs implements vscode.FileSystemProvider {
    private readonly _onDidChangeFile = new vscode.EventEmitter<vscode.FileChangeEvent[]>();
    public readonly onDidChangeFile = this._onDidChangeFile.event;

    constructor(
        protected readonly ctx: vscode.ExtensionContext,
        ...
        protected readonly output: vscode.OutputChannel
    ) { ... }

    watch(_uri: vscode.Uri): vscode.Disposable {
        return new vscode.Disposable(() => {});
    }
    stat(_uri: vscode.Uri): vscode.FileStat {
        return { type: vscode.FileType.File, ctime: 0, mtime: Date.now(), size: 0 };
    }
    readDirectory(uri) { throw vscode.FileSystemError.FileNotADirectory(uri); }
    createDirectory(uri) { throw vscode.FileSystemError.NoPermissions(uri); }
    rename(oldUri) { throw vscode.FileSystemError.NoPermissions(oldUri); }
```

**URI parser pattern — copy structure** (`remoteScriptFs.ts:119-135`):
- Strict regex match; throw `FileSystemError.FileNotFound(uri)` on any failure (defence-in-depth per `:114-118` comment).
- Use `uri.authority` for the identity segment (per RESEARCH Pitfall 1); the path holds `/<eventName>.json`.
- `encodeURIComponent(identity)` on construction; the URI parser auto-decodes `uri.authority`/`uri.path`.

**Diverge from analog:**
- `readFile`/`writeFile` go to `ctx.globalState` not GraphQL+Files REST. Substantially simpler: ~15 lines each vs `remoteScriptFs.ts:190-299`'s ~110 lines.
- `delete` should **delegate to the `altium365.testEvents.delete` command** rather than `throw NoPermissions` (the only behavioural inversion vs the analog) — gives the user a confirmation flow.
- Inject `$schema` field on `readFile`, strip on `writeFile` (RESEARCH §Q2 Layer 2 fallback). The remote FSP has no equivalent.
- No `resolveWorkspace`, no `ensureWorkspaceToken`, no `logFsError` — drop those helpers entirely.

**Registration pattern — copy from `extension.ts:94-98`:**
```typescript
const fsRegistration = vscode.workspace.registerFileSystemProvider(
    'altium365', remoteFs, { isCaseSensitive: true, isReadonly: false }
);
```
Substitute scheme `'altium365-event'`. Push onto `context.subscriptions` per CONVENTIONS.md:185.

### `src/testEvents/identity.ts` (resolveScriptIdentity helper)

function key(fsPath: string): string {
    return process.platform === 'win32' || process.platform === 'darwin'

The CONTEXT D-06 says "branches on `localScriptCache` membership exactly like Phase 6's `activeIsRemoteScript`" — that's the `scheme === 'file' && getLocalScript() !== undefined` half; we add the explicit `altium365:` scheme branch for completeness.
