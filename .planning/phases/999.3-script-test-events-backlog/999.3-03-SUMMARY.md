**Test events now edit as real VS Code text tabs backed by globalState, with dual-layer JSON-schema autocomplete and writeFile as the single commit edge — no save-bridge, no temp files, no disk leakage.**

## Accomplishments
- `TestEventFs` (src/testEvents/eventFs.ts, ~165 lines) implements `vscode.FileSystemProvider` with stat/readFile/writeFile + no-op watch/readDirectory/createDirectory/rename + delete-via-command
- Exported helpers `buildEventUri(identity, eventName)` and `parseEventUri(uri)` keep URI shape centralized — future callers (Plan 04 picker) reuse them rather than concatenating strings
- Dual-layer schema binding live: package.json `contributes.jsonValidation` (Layer 1) + runtime `$schema` injection on read (Layer 2) — autocomplete works even if jsonValidation contribution misfires

## Decisions Made
- `parseEventUri` lowercases only the `.json` suffix check (not the whole path) — preserves case in event names since identities may already be case-sensitive (scriptId GUIDs)
- `stat` returns File unconditionally rather than throwing FileNotFound for missing events — VS Code's `openTextDocument` needs a successful stat before calling readFile; readFile then seeds an empty `{}` event
- Delete dispatches to `altium365.testEvents.delete` (lands in Plan 04) rather than calling `deleteStore` directly — keeps the "are you sure?" confirmation UI in the command layer, not the FSP
