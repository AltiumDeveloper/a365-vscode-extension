<objective>
Add a `Select Workspace` context-menu entry on inactive workspace tree nodes that activates the workspace directly (bypassing the QuickPick), while hiding the entry on the already-active workspace.

Implementation has four mechanical pieces:
1. Split `CTX_WORKSPACE` in `src/sidePanel.ts` into `CTX_WORKSPACE_ACTIVE` (`'workspaceNode-active'`) and `CTX_WORKSPACE_INACTIVE` (`'workspaceNode-inactive'`); assign whichever matches the workspace's active state.
2. Factor the post-pick side-effect block out of `doSelectWorkspace` in `src/extension.ts` into an exported `applyWorkspaceSelection(context, workspace)` helper, then have `doSelectWorkspace` call it.
3. Register `altium365.workspace.selectFromNode` in `src/treeCommands.ts` (with signature `(node?: A365Node) => Promise<void>`); the handler reuses `applyWorkspaceSelection`.
4. Update `package.json contributes.menus['view/item/context']`: add a third workspace entry gated on `viewItem == workspaceNode-inactive`, and update the existing two workspace entries (Copy ID, Open in Browser) from `viewItem == workspaceNode` to `viewItem =~ /^workspaceNode/` so they survive on both active and inactive workspaces.

Purpose: Phase 3 UAT Scenario 4 showed users discoverability gap — they didn't realise they had to use the palette to switch workspaces. A right-click → Select entry on the tree node closes that gap; the contextValue split hides the entry once already active so it doesn't taunt the user with a self-action.

Output: 4-file change. Zero GraphQL/auth surface change (D-15). Existing command IDs and globalState keys preserved (D-16).
</objective>
