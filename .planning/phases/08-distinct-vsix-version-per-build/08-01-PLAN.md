<objective>
Extend the GitHub Actions CI workflow so every push to `main` stamps `package.json` with a unique pre-release version `${BASE}-ci.${GITHUB_RUN_NUMBER}+${SHA7}`, packages the VSIX with `vsce package --pre-release`, and publishes it as an asset on an auto-created GitHub Release. Preserve the existing artifact upload for non-main pushes.

Purpose: Without a distinct version per build, installed copies cannot detect newer artifacts; VS Code treats same-version installs as no-ops. This is the prerequisite that makes the in-extension updater (08-03) useful.

Output: Modified `.github/workflows/ci.yml` that produces a GitHub Release + attached VSIX on every main commit; verifiable by pushing to main and inspecting the Releases page.
</objective>

Modify `.github/workflows/ci.yml` to implement the locked CI-versioning contract. Concrete deltas (per 08-RESEARCH.md lines 397-460 and 08-PATTERNS.md "Net changes" list):

1. **Triggers:** keep `push.branches: [main]`; ADD `pull_request.branches: [main]` so PRs still produce an artifact-only VSIX (CI-VER-03).
2. **Permissions block (workflow level):** add `permissions: { contents: write }` — required for `softprops/action-gh-release@v2` to create releases with the built-in `GITHUB_TOKEN` (08-RESEARCH.md line 408, 461).
3. **Checkout:** keep `actions/checkout@v4`. Add `with: { fetch-depth: 1 }` (only the head commit is needed for SHA7 + commit message).
4. **Setup-node:** keep `actions/setup-node@v4` with `node-version: '20'`.
5. **New step `Compute version`** (id `ver`), guarded `if: github.ref == 'refs/heads/main'`:
   - Reads `BASE` from `package.json` via `node -p "require('./package.json').version"`.
   - Computes `SHA7=$(git rev-parse --short=7 HEAD)`.
   - Builds `VERSION="${BASE}-ci.${GITHUB_RUN_NUMBER}+${SHA7}"`.
   - Writes `echo "version=$VERSION" >> "$GITHUB_OUTPUT"` so later steps can reference `${{ steps.ver.outputs.version }}`.
   - Runs `npm version "$VERSION" --no-git-tag-version --allow-same-version` (runner-only mutation; never committed back).
6. Keep `npm ci` and `npm run compile`. ADD a new step `- run: npm test` BEFORE the package step (gates releases on a green vitest run; `package.json` already defines `"test": "vitest run --passWithNoTests"`).
7. **Split the package step into two `if`-guarded variants:**
   - On main: `npx vsce package --pre-release` (the `--pre-release` flag is required because the version carries a `-ci.N` pre-release tag and is NOT in the existing `npm run package` script per 08-PATTERNS.md line 334).
   - On non-main: `npm run package` (existing behavior — plain VSIX at static version `0.1.0`).
8. Keep the existing `actions/upload-artifact@v4` step unconditional (parallel debugging channel per CONTEXT.md decision).
9. **New step `Create GitHub Release`** using `softprops/action-gh-release@v2`, guarded `if: github.ref == 'refs/heads/main'`:
   - `tag_name: v${{ steps.ver.outputs.version }}`
   - `name: v${{ steps.ver.outputs.version }}`
   - `body: ${{ github.event.head_commit.message }}` (auto-generated from head commit subject per CONTEXT.md decision)
   - `prerelease: true`
   - `files: '*.vsix'`
   - `env: { GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }} }`

**Style rules (verified from existing file):** 2-space YAML indent, single quotes for string scalars (`'20'`, `'*.vsix'`, `'refs/heads/main'`), `actions/*@v4` and `softprops/action-gh-release@v2` major-version pin convention.

**Pitfall #2 mitigation:** Do NOT pre-emptively shift the SHA into the pre-release segment. Ship the locked `${BASE}-ci.N+SHA7` form first; if a subsequent CI run fails on `vsce package --pre-release` with "invalid version", the documented fallback is to switch to `${BASE}-ci.${RUN}.${SHA7}` (08-RESEARCH.md line 332). Do not pre-implement the fallback in this plan.
