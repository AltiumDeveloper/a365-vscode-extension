# Phase 02.1 Plan 04: Active Workspace Cue Summary

**Tree now highlights the most-recently-exchanged workspace with a filled `cloud` icon + `(active)` description; inactive workspaces dim to a `descriptionForeground` cloud.**

## Performance

- **Duration:** ~3 min
- **Tasks:** 2
- **Files modified:** 2

## Accomplishments
- New `getActiveWorkspaceId(context)` accessor in `src/auth.ts` (sync, returns `string | undefined`)
- `ensureWorkspaceToken` records the active workspaceId in `globalState['altium365.activeWorkspaceId']` after a successful token exchange (and only after — cache-hits don't touch it)
- `clearAllTokens` drops the active-id alongside the existing token wipe — sign-out → no stale active cue
- `A365TreeDataProvider.getTreeItem` `case 'workspace'` reads the active id per render and varies the `ThemeIcon` + `description` accordingly

## Files Created/Modified
- `src/auth.ts` — new constant `GLOBAL_ACTIVE_WORKSPACE_KEY`, write in `ensureWorkspaceToken`, delete in `clearAllTokens`, new exported `getActiveWorkspaceId`
- `src/sidePanel.ts` — import `getActiveWorkspaceId`, conditional icon + `(active)` description in workspace TreeItem branch

## Decisions Made
- **Exchange-path-only write** for the active id (plan offered both choices) — D-06 says "most recently *exchanged*", so cache-hits intentionally don't update the marker. This also keeps the write off the hot path when the user has already settled on a workspace.
- **`ThemeColor('descriptionForeground')` for the inactive cloud** — the plan permitted either `cloud-outline` (if it existed) or the ThemeColor fallback. `cloud-outline` is not in the standard VS Code codicon set, so the ThemeColor approach is the only working option without bundling custom SVG icons.
- **Active-id write placed *after* the workspace-index update** — strict ordering guarantees that a failure in `exchangeWorkspaceToken`, `secrets.store`, or the index update aborts before any workspace is marked active.
