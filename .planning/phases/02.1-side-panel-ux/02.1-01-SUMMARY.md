**A365TreeDataProvider now emits two synthetic `Projects (n)` / `Scripts (n)` category rows per workspace, with each category lazily reading from a kind-keyed per-workspace cache populated by the single workspace fetch.**

## Accomplishments

- Reversed Phase 02 D-05 flat-sibling layout — workspace expansion now yields exactly two category rows
- Preserved single-round-trip performance contract: one workspace expand = one `Promise.all([listProjects, listScripts])`, category expansion is pure cache read
- Empty categories still render as `Projects (0)` / `Scripts (0)` so the structure is predictable (G-01 requirement)
- New contextValues `projectsCategoryNode` / `scriptsCategoryNode` are isolated from existing script/project menus so future plans (02.1-03, 02.1-05) can target the leaf nodes without category leakage
- `refresh(node)` is exhaustive over all five interactive kinds (workspace, projectsCategory, scriptsCategory + per-leaf no-ops)

## Decisions Made

- **Cache split:** Used two separate `Map<string, A365Node[]>` caches (projectsCache / scriptsCache) instead of one union map. Cleaner per-category refresh semantics; matches the D-02 contextValue split; trivially extensible if future kinds (e.g. components) join the hierarchy.
- **Missing-cache fallback:** Category expansion on a missing cache returns `[]` rather than triggering a fresh fetch. Per plan: "cache MUST have been populated by the parent workspace expansion; if missing, treat as empty array and let the next manual refresh repopulate." Keeps category resolution synchronous and side-effect-free.
- **ThemeIcon choice:** Used `folder-library` per D-03 — codicon exists and reads as "collection of folders/files" which differentiates well from leaf `folder` (projects) and `file-code` (scripts).
