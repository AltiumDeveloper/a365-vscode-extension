<objective>
G-05 closure: extend the GraphQL workspace + project queries to request `url`, propagate it onto tree-node payloads, and add an `Open in Browser` context menu item on workspace and project nodes that opens the URL via `vscode.env.openExternal`.

Purpose: jumps the developer from VS Code straight into the A365 web view for the relevant workspace or project, removing the manual URL-hunt step.
Output: extended types/queries in `src/workspace.ts`, additional payload fields in `src/sidePanel.ts`, two new handlers added to the `registerTreeCommands` factory in `src/treeCommands.ts`, two new commands + two new view/item/context entries in `package.json`, no changes to `src/extension.ts` beyond ensuring the existing `registerTreeCommands` wiring (added by Plan 02.1-03 Task 4) continues to spread the disposables.

Depends on 02.1-01 (sidePanel TreeItem construction sites must already use the post-restructure code shape) AND on 02.1-03 (treeCommands.ts module must already exist and be wired into activate — this plan only extends it; it does NOT re-create the factory).

**Backend assumption:** Phase 02 HUMAN-UAT.md G-05 states "Workspaces and projects expose a `url` field (`DesWorkspaceInfo.url`, `DesProject.url`) on their GraphQL types." This plan trusts that statement. If during execution the GraphQL backend rejects the `url` selection with an "unknown field" error, the executor MUST stop and surface the failure — the gap-closure intent is unfulfillable without backend support. Do NOT silently fall back to a hand-constructed URL.
</objective>
