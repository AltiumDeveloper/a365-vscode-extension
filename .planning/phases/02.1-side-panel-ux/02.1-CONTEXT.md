## Phase Boundary

Resolve the 5 UX gaps the user identified while exercising the Phase 02 side panel against a live A365 workspace. All changes are incremental refinements to the existing `A365TreeDataProvider` + `package.json` contributes surface — no new GraphQL endpoints, no new auth scope, no new runtime dependencies.

In scope:
- Restructure tree hierarchy under a workspace (category parent nodes for projects / scripts)
- Clean up tree labels (drop GUIDs) and surface GUIDs via a context menu instead
- Visually distinguish the active workspace
- Add a view-title shortcut for environment switching
- Add `Open in Browser` to workspace + project context menus

Out of scope (carry forward to Phase 3):
- SCRIPT-01 run-local-from-tree flow (still deferred per Phase 02 VERIFICATION.md)
- Anything in `02-REVIEW.md` (CR-01/CR-02 etc. — addressed separately via `/gsd-code-review-fix` or a dedicated phase)

<decisions>
## Implementation Decisions

### Tree Hierarchy (G-01)
- **D-01 (REVERSES Phase 02 D-05):** Workspace children are two synthetic category nodes — `Projects (n)` and `Scripts (n)` — where `n` is the count of items in that category. Each category lazy-loads its real children on expand. Empty categories still render (showing `(0)`) so the structure is predictable.
- **D-02:** New context values `projectsCategoryNode` and `scriptsCategoryNode` are introduced so the category rows don't accidentally inherit project/script context menus.
- **D-03:** Category nodes use `folder-library` (or similar) ThemeIcon; individual project nodes keep the existing `folder` icon; individual script nodes keep the existing `file-code` icon.

### Labels & Identity (G-02)
- **D-04:** `TreeItem.label` for workspaces, projects, and scripts contains only the human name — backend GUIDs are stripped from the displayed string. The GUID stays on the node payload so commands can read it.
- **D-05:** A new command `altium365.tree.copyId` is registered. It accepts a tree node, reads `node.id`, and calls `vscode.env.clipboard.writeText`. A `view/item/context` entry exposes it on `workspaceNode`, `projectNode`, and `scriptNode`. Title in the menu: `Copy ID`.

### Active Workspace Cue (G-03)
- **D-06:** "Active workspace" = the workspace whose token was most recently exchanged via `ensureWorkspaceToken` (the one the user implicitly switched to). The accessor lives in `src/auth.ts` (or `src/workspace.ts` — planner decides based on where the active-workspace id is already tracked) as a new exported function returning `string | undefined`.
- **D-07:** In the tree, the active workspace node uses `ThemeIcon('cloud')` (filled) while inactive workspaces use `ThemeIcon('cloud-outline')` (or `cloud` with a `ThemeColor('descriptionForeground')`). Additionally, the active workspace's `TreeItem.description` is set to `"(active)"` for screen-reader clarity.

### View Title Action (G-04)
- **D-08:** A `menus.view/title` entry is added for the existing `altium365.selectEnvironment` command (the actual id in `package.json:72` / `src/extension.ts:61`, also reused by the status-bar QuickPick at `extension.ts:89`), gated by `view == altium365.tree && altium365.signedIn`. Icon: `$(globe)`. No new command handler — reuses the existing one. (Notes: the existing view id is `altium365.tree`, not `altium365.workspaces` as G-04 originally said; and the existing command is `selectEnvironment`, not `switchEnvironment` — both confirmed by the planner against the live codebase.)

### Open in Browser (G-05)
- **D-09:** `LIST_WORKSPACES_QUERY` and `LIST_PROJECTS_QUERY` in `src/workspace.ts` are extended to request the `url` field. `WorkspaceInfo` and `ProjectInfo` types gain `url?: string`. Tree nodes carry the URL on the node payload.
- **D-10:** Two new commands — `altium365.workspace.openInBrowser` and `altium365.project.openInBrowser` — call `vscode.env.openExternal(vscode.Uri.parse(node.url))`. If `node.url` is missing, show an info toast `"This {workspace|project} does not expose a browser URL"`. Two corresponding `view/item/context` entries.

### Code Organization
- **D-11:** Tree-generic command handlers (Copy ID, Open in Browser) live in a new module `src/treeCommands.ts` — kept separate from `src/scriptCommands.ts` because they are not script-scoped. A `registerTreeCommands(ctx)` factory mirrors the existing `registerScriptCommands` pattern.

### the agent's Discretion
- Exact ThemeIcon for category nodes (planner can substitute `database` / `symbol-folder` / `folder-library` based on visual fit).
- Exact wording of `description` suffix for the active workspace ("(active)" vs "• active" vs an icon-only cue).
- Whether `Copy ID` shows a small toast confirmation after copy (default: yes, short info message).

</decisions>
