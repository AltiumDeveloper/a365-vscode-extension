# Quick Task 260605-b3m: Fix spawn python ENOENT on macOS

## Symptom

```
[Altium 365] pip launch failed: spawn python ENOENT
```

macOS does not ship `python` (only `python3`). The extension should fall back
to `python3` on non-Windows platforms.

## Root cause

`resolvePythonPath()` in `src/runner/index.ts` reads `details.path` from the
MS Python extension API (`api.environments.getActiveEnvironmentPath(resource)`)
without validating it is an absolute path. When the Python extension returns
a bare command name such as `"python"` (e.g. the active interpreter is set
to a conda env that has just `python` in PATH, or the API returns the
interpreter id rather than the full path), the bare name is used directly,
bypassing the macOS fallback `'python3'`.

## Fix (1 task)

**File:** `src/runner/index.ts` — `resolvePythonPath`

Change:
```typescript
if (details?.path) {
    return details.path;
}
```
To:
```typescript
if (details?.path && path.isAbsolute(details.path)) {
    return details.path;
}
```

This ensures only absolute paths from the Python extension are trusted.
A bare command name falls through to the platform default:
- macOS / Linux → `python3`
- Windows → `python`

`exec[0]` from `getExecutionDetails` is kept as-is: it may be a full path
or a short name, but it's the user's explicit executor choice and should be
respected. If the user explicitly configured the Python extension with
`"python"` as the executable and it's on their PATH, that is their intent.
Only the passive `getActiveEnvironmentPath` result is filtered.
