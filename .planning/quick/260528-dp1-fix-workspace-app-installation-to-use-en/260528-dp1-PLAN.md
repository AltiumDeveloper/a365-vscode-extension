# Quick Task: Fix Workspace App Installation to Use Environment-Specific App GRIDs

## Problem

Task 260528-dhr introduced `getAppIdForEnvironment()` that guesses the app GRID from the GraphQL endpoint URL via string matching (e.g., `endpoint.includes('dev')`). This is incorrect and fragile because:

1. The extension already has proper environment switching via "Switch Environment" command
2. Environment is stored in `altium365.activeEnvironment` setting
3. Each environment spec in `altium365.environments` config should have its own `appId` field
4. URL-based guessing can fail when environments use unexpected URLs or custom deployments
5. Dev environment must check ONLY Dev GRID, UAT ONLY UAT GRID, Prod ONLY Prod GRID

**Root cause:** Architectural misalignment — inferring configuration from URLs instead of using the existing environment config system.

## Solution

Add `appId` field to environment specs and have callers read it from the active environment config, removing the URL-guessing function entirely.

## Objective

Replace URL-based app GRID guessing with proper environment configuration lookups, ensuring each environment uses its correct app GRID from settings.

**Purpose:** Eliminate fragile URL pattern matching and align app installation with the extension's environment switching architecture.

**Output:** Environment specs with `appId` field, updated app installation functions that accept `appId` as parameter, removal of `getAppIdForEnvironment()`.

## Context

- Active environment: `altium365.activeEnvironment` setting
- Environment specs: `altium365.environments` config object
- Environment switching: `doSelectEnvironment()` in `src/extension.ts`
- App installation: `checkAppInstalled()` and `installApp()` in `src/workspace.ts`
